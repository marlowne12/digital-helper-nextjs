# Fiverr Customer Response System

Use this as the inbox playbook for Fiverr buyer questions. It is built to keep replies fast, protect Mars from vague scope, and push unclear work into one focused custom offer.

## Operating Boundary

- Draft replies only; Mars sends messages manually.
- Do not accept work that requires payment handling, regulated compliance, identity verification, or platform terms.
- Do not request secrets before scope is agreed. If access is needed, ask for temporary/test access through the Fiverr order thread after purchase.
- Keep the canonical offer centered on Custom OpenClaw / AI automation skills. Chatbot, GEO, and n8n requests can be answered, but should become custom-scoped work unless Mars has published those separate gigs.

## Triage Rules

### Green Light

Use a package recommendation when the buyer provides:
- A specific repeated task, workflow, website, or tool stack
- 2-3 examples of current manual output
- A clear desired final output
- Known constraints, deadline, and tools involved

### Needs Clarification

Ask questions before pricing when the buyer says:
- "Can you automate my business?"
- "I need AI for everything"
- "Can you connect all my tools?"
- "Build me a full app"
- "Make ChatGPT rank my site"
- "I need a chatbot like ChatGPT"

### Escalate To Custom Scope

Do not let the buyer self-order a base package when the work includes:
- Multiple apps, APIs, or data sources
- Scheduled execution or ongoing monitoring
- CRM, email platform, or database integration
- Website installation, embed code, or deployment help
- Any unclear ownership of content, data, or accounts

### Decline

Politely decline or narrow the request if it involves:
- HIPAA, medical, legal, tax, finance, or high-stakes compliance
- Payment processing inside a bot or automation
- Full SaaS/app builds with auth and database
- Guaranteed sales, SEO rankings, AI search placement, or platform approval
- Scraping private data, spam outreach, account abuse, or bypassing protections

## Package Fit Rules

- Basic / Simple Skill: one input, one output, text-based SKILL.md, README, and tested sample output.
- Standard / Workflow Skill: multi-step process, conditional logic, formatting, or light scripting.
- Premium / Integrated Skill: API/tool integration, multi-source inputs, fuller documentation, or more setup guidance.
- Custom Offer: unclear scope, multiple systems, rush deadline, website install, or anything outside the listed package limits.

## Saved Replies

### First Response

Thanks for reaching out. I can help if this is a focused repeatable workflow.

To point you to the right package, please send:

1. The task, website, or tool stack involved
2. What happens now, step by step
3. 2-3 examples of the current manual output
4. The exact final output you want
5. Any tools, privacy rules, or deadline constraints

Once I have that, I can tell you whether Basic, Standard, Premium, or a custom offer is the cleanest fit.

### Package Fit

Based on what you described, this looks like a [Basic / Standard / Premium / custom] fit.

Before you order, I want to confirm:

1. The main input will be: [input]
2. The final output should be: [output]
3. The tools involved are: [tools]
4. The scope does not include: [excluded items]

If that matches, I can move forward cleanly.

### Custom Skill Builder

Yes, this is a good fit for a custom AI skill if the task has a repeatable pattern.

Please send:

1. The task you repeat
2. 2-3 examples of the current manual output
3. The exact output format you want
4. Any tools involved
5. Any privacy or "do not do this" rules

I will package the workflow into a documented skill with test examples so you can reuse it.

### Too Broad

This sounds larger than the base packages, so I do not want you to order the wrong thing.

The clean next step is to break it into one focused workflow or one first version. Send me the single most important task you want automated first, and I will scope a smaller package or custom offer around that.

### Integration Check

This may be possible, but integrations depend on the tools and access involved.

Please send:

1. The apps/tools you want connected
2. What should trigger the workflow
3. What should happen in each tool
4. Whether API access, Zapier, Make, n8n, or webhooks are available
5. Any deadline or privacy constraints

Please do not send passwords or API keys yet. If access is needed, I will explain the safest way after scope is confirmed.

### Chatbot Clarifier

Yes, I can scope a focused website chatbot for lead capture and common questions.

Please send:

1. Your website URL
2. Website platform, if known
3. 5-10 common visitor questions
4. Lead fields you want collected
5. Where leads should go
6. Any brand or style requirements

If this needs live AI, CRM sync, or website installation, I will confirm a custom scope before you order.

### GEO Clarifier

Yes, I can audit your website for AI search visibility.

Please send:

1. Company name
2. Website URL
3. Top 3 products or services
4. Ideal customer
5. 2-3 competitors
6. Main search query you care about

Quick note: I do not guarantee ChatGPT rankings, AI recommendations, or search placement. The audit gives you gaps and prioritized fixes.

### Automation Clarifier

Yes, this sounds like an automation workflow.

Please send:

1. What triggers the workflow
2. Which apps/tools are involved
3. What should happen step by step
4. Whether you already use n8n, Zapier, or Make
5. Whether AI is involved
6. What the final output should look like

If credentials or API keys are needed, I will tell you exactly what is required after scope is confirmed.

### Credential Boundary

Please do not send passwords, API keys, payment details, or private credentials in this first message.

If the project needs access, I will first confirm the scope, then ask for the safest option inside the Fiverr order thread, such as temporary access, test credentials, or screenshots.

### Not A Fit

Thanks for the details. I do not think this is a good fit for my Fiverr packages because it involves regulated compliance, payment handling, platform abuse risk, or a larger software build.

I would rather be clear before you spend money. If you can narrow this to one non-sensitive workflow, I can take another look.

## Order Intake Checklist

Before accepting or starting:

- [ ] Buyer described one primary workflow
- [ ] Buyer provided 2-3 examples or sample inputs
- [ ] Desired output format is explicit
- [ ] Tools/platforms are named
- [ ] Scope exclusions are written in the thread
- [ ] Delivery package or custom offer is confirmed
- [ ] No secrets are requested before order scope is clear
- [ ] Deadline fits Mars's available time

## Post-Order Kickoff

Thanks for the order. I am reviewing the details now.

If anything is unclear, I will ask before building. Otherwise I will send:

1. Brief implementation plan
2. First test output or preview
3. Final files and usage notes

Please keep all examples and requirements in this Fiverr order thread so the scope stays clean.

## Escalation Boundaries

Ask Mars before replying when:
- The buyer asks for a rush delivery, discount, call, or ongoing support.
- The buyer wants a custom offer above the listed package scope.
- The buyer asks to move communication off Fiverr.
- The buyer requests credentials, account changes, publishing, payment setup, or legal/compliance handling.
- The work could affect a real customer, real money, production account, or public posting.

Decline without negotiation when:
- The request is illegal, deceptive, spammy, or credential-stealing.
- The buyer demands guaranteed revenue, rankings, or platform approval.
- The work requires regulated professional advice or high-stakes decisions.

## Lightweight Daily Workflow

1. Open Fiverr inbox once in the morning and once after work.
2. For each unread message, tag it mentally: green light, clarify, custom, decline, or Mars approval.
3. Paste the closest saved reply and customize only the bracketed details.
4. If the buyer answers clearly, map to Basic, Standard, Premium, or custom offer.
5. If the buyer stays vague after one clarification, send Too Broad and wait.
6. For active orders, keep every scope decision in the Fiverr thread.
7. End each check by writing the next action in one line: waiting on buyer, send custom offer, start build, needs Mars approval, or decline.
